# 自動更新パイプライン整備 (2026-05-23, phase 7 task ⑥)

レビュー指摘「新試験回の追加が手動なら半年放置は無理」「2026年最新銘打つ記事は
半年単位でメンテ必須」への対応。風化耐性の構造的弱点を洗い出し、自動でロール
フォワードする部分とそうでない部分を明確化した。

## この PR で入れた構造

1. `lib/constants/current-year.ts` — JST ベースの `CURRENT_YEAR` / `CURRENT_REIWA`
   単一ソース。blog ジェネレータが import して 【YYYY年最新】 系タイトルを
   デプロイ毎に自動更新（従来 generators.ts ローカル定義だったものを共有化）。
2. `lib/constants/exam-schedule.ts` — IPA 春期/秋期の試験日マスタ +
   `nextExamSitting()`。試験日が過ぎると自動で次回（翌年春期含む）へ繰り上がる。
3. `lib/dashboard/analytics.ts::daysUntilNextExam()` をマスタ参照へ置換。
   「次の試験まで N 日」がコード重複なく自動更新。

## 半年放置時に発生する手動作業の洗い出し

放置しても自動で陳腐化しないもの（=手当て不要）:

- 「{現年}年最新」系ブログタイトル → `CURRENT_YEAR` で自動ロールフォワード
- 「次の試験まで N 日」カウントダウン → `nextExamSitting()` で自動繰り上げ
- 既存問題ページ・サイトマップ・内部リンク → 静的データなので陳腐化しない

放置すると陳腐化する/手動対応が要るもの:

- 新試験回の問題追加 → `logs/exam-update-recipe.md` の半自動フロー（約1〜1.5h/区分）。
  頻度: 年2回（春期4月・秋期10月の合格発表後、問題公開時）。
- IPA が試験日の正確な日付を変更した場合 → `lib/constants/exam-schedule.ts` の
  month/day を 1 箇所更新。頻度: 年1回程度、所要1分。
- 制度改定（CBT 移行、区分統廃合）→ 稀。発生時に手動対応。
- 特定年度を固有名で書いた記事（例: generators.ts の「2024〜2025年で増えた論点」）
  → 意図的な歴史記述。陳腐化はするが事実としては不変なので緊急性は低い。

## 各作業の所要時間と頻度（サマリ）

- 試験日の月日更新: 1 分 / 年1回
- 新試験回の問題追加: 1〜1.5 時間/区分、全区分で半日〜1日 / 年2回
- それ以外: 自動

## 結論

「半年完全放置」でもサイトは陳腐化表示を最小化できる状態になった。
唯一の必須手動作業は **年2回の新試験回の問題追加**（半自動・半日〜1日）と
**年1回の試験日微修正**（1分）。これらは `exam-update-recipe.md` に手順化済み。
