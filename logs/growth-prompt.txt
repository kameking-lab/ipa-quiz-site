■ 開始手順
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. `git checkout growth-integration` し `git pull --ff-only`。（絶対に main へ checkout/commit/merge/push しない）
2. `logs/growth-worklog.md`（done/SKIP/保留）と `logs/growth-backlog.md`（優先度順）を読む。
3. 未着手の最優先1件を選ぶ。着手前にコード・git log で既に実装/対処済みでないか必ず確認（二重実装防止）。済みなら worklog に done を追記して次へ。

■ 1改善 = 1サイクル
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
A. 対象を read-only 監査（まず読む。憶測で直さない）。
B. 実害/効果のある1点に絞り最小diffで実装。広域リファクタ禁止。1コミット=1論点。
C. 全緑ゲート: `pnpm typecheck` `pnpm lint` `pnpm test` `pnpm build` すべて緑。1つでも落ちたら戻して worklog に「未解決(理由)」を記録し別タスクへ。
   ※ゲートは commit と別の呼び出しで実行し、緑を目視してから commit（同一バッチに混ぜない）。
D. 「崩れたら落ちる」検証を必ず添える。順位はGoogle次第なので測らない。代わりに**実装が正しく入ったか**を実測:
   - ページ追加/導線 → localhost 本番ビルドへの Playwright か、`.next`成果物/HTMLへの curl/grep で「ページ実在・SSRでHTML出力・リンク先200・JSON-LD/メタ妥当」を確認。
   - 404解消 → 対象URLが 200 か 301(正しい行先) か 410 になったことを実測。新たな404を作らない。
   - 数値/メタ → 実値を grep で確認。
   可能なら回帰テストを追加（夜間第1弾の流儀）。
E. 緑かつ実測OKなら関連ファイルのみ commit（英語または日本語の簡潔メッセージ、何を・なぜ）。末尾に Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>。
F. `git pull --ff-only` 後 `git push origin growth-integration`。競合したら pull してから再push（rebase/force/履歴改変 禁止）。
G. worklog に done/SKIP/未解決 と コミットSHA・検証内容 を追記。

■ 絶対安全原則
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- main へ push/merge しない。作業は growth-integration のみ。本番デプロイを起こさない。
- 禁止: DBスキーマ破壊的変更 / env・KV・シークレット編集 / 価格・無料枠の数値を勝手に有効化 / force push・履歴改変 / 依存メジャー更新 / 広域リファクタ / 新規外部API契約。
- 過大修正の罠: 理論上の指摘で実害なしは直さず worklog に SKIP 記録。迷ったら直さず SKIP（安全側）。
- 「対応した」の自己申告禁止。実測・テストで検証してからコミット。
- コンテンツ生成（ブログ・解説・LP文言）は著作権クリーンな**オリジナル生成**。第三者著作物・IPA問題文の長文転載をしない（出典リンクは可）。
- AIコスト: 新規の重いAI呼び出しを既定で大量発火させない（ビルド時/ページ表示時に勝手にLLMを叩かない）。
- 戦略判断そのもの（料金をいくらにする/課金を有効化する/無料枠を変える 等）は自律実行しない。`logs/growth-human-decisions.md` に積んで次へ（暴走で戦略を勝手に確定しない）。CLAUDE.md の「承認必須事項」も同様。
