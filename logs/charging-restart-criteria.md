# 課金システム復活の判断基準・手順

このドキュメントは、教育貢献プロジェクトとして全機能無料で運営している過去問 AI を、
将来的に有料プランへ戻す際の判断基準と切り戻し手順を記録するものです。

最終更新: 2026-04-28

---

## 1. 復活トリガー（次のいずれかが満たされた場合に検討）

| # | 条件 | 詳細 |
|---|------|------|
| 1 | M6（兼業 NG ロック）の解除 | 主業務側の規定が変更され、兼業として有料サービスを提供できる体制になったとき |
| 2 | 法人化の準備が整った | 個人運営から法人運営へ切り替え、経理・税務・契約面での課金受領体制が確立したとき |
| 3 | 月次運営費が手出し限界を超える | AI 利用費が月 50,000 円を超え、シェア・フィードバック経由の負担分散では運営継続が困難になったとき |
| 4 | 法人ユーザーからの実需が累計 5 件以上集まった | `/contact` 経由で「企業活用」「教育機関活用」のご相談が複数集まり、Team プラン需要が確認できたとき |
| 5 | コミュニティが「課金で応援したい」と望んだ | フィードバック・X 上で「お金を払いたい」声が一定数（目安 50 件以上）集まったとき |

これらは AND ではなく OR 条件です。複数満たすと優先度が上がります。

## 2. 復活時のチェックリスト（1 日で完了する設計）

### 2.1 コード復活手順

1. Vercel の環境変数で `NEXT_PUBLIC_PAID_MODE=true` を設定する
   - これだけで `/api/stripe/checkout`, `/api/stripe/portal`, `/admin/team` が再活性化する
   - `lib/paid-mode.ts` の `PAID_MODE` がフラグの単一ソース
2. Stripe 商品の活性化
   - `STRIPE_PRICE_ID_PREMIUM`, `STRIPE_PRICE_ID_TEAM` を有効な price ID に差し替え
   - 商品自体は削除せず非アクティブ状態で保持しているため、Stripe ダッシュボードから「アクティブ化」のみで復元可能
3. UI 復活（10 分以内で完了する想定）
   - `/account` ページの「現在のプラン」セクションを再表示（PAID_MODE 分岐を追加）
   - `/pricing` を旧 3 プラン比較表に戻す（Git 履歴: `feat(phase1)` 以前）
   - `PremiumUpsellDialog` を `git revert` で復活、`QuizPlayer` の参照差し替え
   - レート制限を `FREE_INITIAL_LIMIT=50` に戻す
4. デプロイ後の確認
   - テスト決済（Stripe Test Mode）→ 本番決済の順で疎通確認
   - `/account?checkout=success` のメッセージが正しく表示されること
   - `/admin/team` がログイン後にアクセスできること

### 2.2 メッセージング復活手順

- `/about`, `/operator`, `/transparency` のステータスを「教育貢献プロジェクト」から「Premium 利用可」併記に変更
- ホーム画面のヒーローを「全機能無料」→「無料でも十分使える / Premium で更に充実」に変更
- フッターの緑バッジ「教育貢献プロジェクト」は維持（プロジェクト精神は変えない）

### 2.3 ユーザーへのアナウンス

- 復活前に最低 30 日の事前告知を `/transparency` と公式 X で公開する
- 既存無料ユーザーには急な制限変更を行わない（過去 30 日アクティブユーザーは経過措置として 1 ヶ月の Premium トライアル付与を検討）
- フィードバック投稿者には「ほぼ無制限」を維持（信頼維持）

## 3. 復活時に**変えない**項目

教育貢献プロジェクトの精神は、課金復活後も以下を維持する。

- 全試験区分・全モード・問題コンテンツは引き続き無料アクセス
- AI コパイロットの初回 10 回無料 + フィードバック投稿でほぼ無制限の仕組みは継続
- フィードバック・問題コメント・透明性レポートは継続公開
- IPA 出典の明示と公式 PDF リンク

## 4. 保持されている資産

復活時にすぐ使えるよう、以下のコード・ドキュメントは削除せず保持している。

| 資産 | 場所 | 状態 |
|------|------|------|
| Stripe Checkout API | `app/api/stripe/checkout/route.ts` | PAID_MODE フラグでガード中 |
| Stripe Portal API | `app/api/stripe/portal/route.ts` | PAID_MODE フラグでガード中 |
| Stripe Webhook | `app/api/webhooks/...` | プラン同期ロジックを保持 |
| プラン定義 | `lib/plans/index.ts` | FREE/PREMIUM/TEAM の 3 プランを保持 |
| Stripe クライアント | `lib/stripe/client.ts`, `lib/stripe/plans.ts` | キー取得とプラン→価格マッピング |
| Team ダッシュボード | `app/admin/team/page.tsx` | PAID_MODE フラグで notFound() ガード |
| Billing Actions UI | `app/account/BillingActions.tsx` | コンポーネントのみ保持、現在は未使用 |
| 認証・Prisma | `lib/auth/...`, `prisma/schema.prisma` | User.plan, stripeCustomerId カラム保持 |

## 5. 復活しない選択肢

以下の場合は、課金復活ではなく別の道を選ぶ可能性がある。

- 受益者負担モデルが教育機関の利用を妨げると判明した場合
- AI コスト改善（モデル変更・キャッシュ）で持続可能性が確保できた場合
- 寄付モデル（OpenCollective 等）で運営費が賄える見込みが立った場合

その場合、本ドキュメントは「課金復活ではなく寄付モデル化の検討」として更新する。
