## 4. 内部リンク構造最適化案

### 4-1. 試験ハブ → 分野ハブ → 問題 の三層リンク
- 試験ハブ (`/ap`) には分野別カードが既にある想定。各カードから
  `/ap/topic/<category>` へ
- 分野ハブ → 各問題へ
- 各問題 → 同分野の関連問題 5 件「次に解くべき問題」リンク（PR 候補）

### 4-2. 関連問題サジェスト
- `/q/[id]` ページ末尾に「同じ topicTags の関連問題 N 件」セクション
- 学習動線の自然な続きを作りつつ、内部リンクで PageRank を分配

### 4-3. ブログ ⇔ 個別問題 相互リンク
- ブログ記事中で言及した問題 ID を JSON-LD `mentions` で関連付け
- 個別問題ページに「この問題を解説したブログ記事」セクション

### 4-4. 試験区分間の橋渡し
- 「AP 受かったら次は SC？ DB？」のような次ステップ提案ブロック
- `/ap` → `/sc`, `/ap` → `/db`, `/ap` → `/nw` などの誘導

### 4-5. アンカーテキスト統一
- "詳しく見る" のような generic テキストではなく、リンク先のキーワードを
  含むアンカー（「FE 基本情報 過去問」など）に統一
- 既存実装も多くは適切だが、フッターや UI 共通部品で `→` のみのリンクが
  ある場合は強化候補

## 6. 工数とコストの目安

LP 大量生成系（合計 約 300 ページ）:
- LLM 生成テンプレ + 人による品質チェック前提
- 1 ページあたり 400〜600 字、内部リンク 5〜10 本
- Gemini Flash-Lite で生成: 1 ページ 約 0.05 円、合計 約 15 円
- 編集レビュー工数が支配的（1 ページ 5〜10 分 × 300 = 25〜50 時間）

リンク構造系（11〜14）:
- 既存テンプレ拡張のみ。1〜3 日の実装

総合判断:
- まず「直前期 LP」「試験 × 計算問題ルート」「関連問題サジェスト」を
  優先実装すれば、低工数で 90 ページ＋全問題ページの内部リンク強化が
  得られる
- 大量生成 LP は「教育価値を損なわない範囲」というプロジェクト戦略に
  照らして、低品質ページの量産は避けるべき。代わりに 30〜50 LP に
  絞った高品質運用を推奨
