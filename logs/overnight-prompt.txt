■ 1改善 = 1サイクル（厳守するループ規律）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
A. 対象領域を read-only で監査（まず読む。grep/Read 中心。憶測で直さない）。
B. 実害のある問題を1つに絞り、最小 diff で修正する。広域リファクタ禁止。1コミット=1論点。
C. 全緑ゲート: `pnpm typecheck` `pnpm lint` `pnpm test` `pnpm build` を実行し、すべて緑であること。
   1つでも落ちたら修正を `git checkout -- <file>` 等で戻し、worklog に「未解決(理由)」を記録して別タスクへ。
D. 「崩れたら落ちる検証」を必ず添える:
   - 挙動の変更 → localhost 本番ビルド(`pnpm build && pnpm start`)に対する Playwright E2E、または既存E2Eの追加/実行。
   - 数値/メタ/JSON-LD/sitemap → `.next` 成果物 or localhost への curl/grep で「実際の値」を確認（理論でなく実測）。
   検証が通らなければ修正を破棄し「未解決」記録。
E. 通ったら `git add -p` 相当で関連ファイルのみ `git commit`（日本語の簡潔なメッセージ、何を・なぜ）。
   コミットメッセージ末尾に Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com> を付ける。
F. `git push origin overnight-integration` する（pull --ff-only 後に push。コンフリクトしたら rebase ではなく
   いったん pull してから再 push。履歴改変・force push 禁止）。
G. worklog に「done: <タスク> / コミットSHA / 検証内容」を追記する。
