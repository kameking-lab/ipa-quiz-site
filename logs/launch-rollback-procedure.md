# 障害時ロールバック手順書

作成日: 2026-05-16
対象: 過去問AI (https://www.kakomon-ai.jp) のローンチ後障害対応

本ファイルは障害発生時に本人が手動で実施する手順書。
障害レベルに応じて「全体ロールバック」または「部分機能停止」を選択する。

---

## 障害レベル判定

### レベル1: 軽微（継続運用）
- 一部 UI の表示崩れ
- 非致命的な JS エラー（Sentry に登録されているが機能は動作）
- AI コパイロットの単発タイムアウト

対応: ログに記録し、次の通常 PR で修正。ロールバック不要。

### レベル2: 中程度（部分機能停止を検討）
- AI コパイロットが全ユーザーで断続的にエラー
- /admin/* 系が正常アクセスできない
- 特定の試験区分ページが 500 エラー

対応: 後述「部分機能停止手順」を実施。全体ロールバックは不要。

### レベル3: 致命的（全体ロールバック）
- サイト全体が 500 エラー
- ユーザーデータ漏洩が疑われる事態
- Vercel デプロイが壊れてホームが表示されない

対応: 後述「Vercel Dashboard 経由のロールバック手順」を即実施。

---

## 手順 A: Vercel Dashboard 経由のロールバック

### 直前安定リリースへのロールバック

1. https://vercel.com/dashboard を開く
2. ipa-quiz-site プロジェクトを選択
3. 「Deployments」タブをクリック
4. デプロイ一覧から、障害が発生していない直前の安定デプロイを探す
   目安: 現在の main HEAD (2094163) の 1〜2 個前のデプロイ
5. 対象デプロイの「...」（ケバブメニュー）をクリック
6. 「Promote to Production」をクリック
7. 確認ダイアログで「Promote」を押す
8. Vercel が古いバージョンを本番に昇格させる（1〜2分で完了）
9. https://www.kakomon-ai.jp にアクセスして正常表示を確認

ロールバック後の確認:
- [ ] ホームページが表示される
- [ ] /ap で試験区分ページが表示される
- [ ] AI コパイロットが動作する

### Twitter での告知

ロールバック中はユーザーへの告知を出す:

「【メンテナンス中】ただいまサービスの一部に不具合が発生しており、復旧作業中です。ご不便をおかけしております。 @kakomon_ai_jp」

復旧後:

「【復旧完了】先ほどの不具合が解消されました。引き続きご利用ください。 @kakomon_ai_jp」

## 手順 B: 部分機能停止

### B-1: AIコパイロット停止

AI コパイロットが障害の原因の場合、env 変数で無効化できる。

手順:
1. Vercel Dashboard > Settings > Environment Variables を開く
2. GEMINI_API_KEY を探す
3. 値を一時的に空文字列に変更する（または変数を無効化する）
4. Vercel が自動再デプロイする（1〜2分）
5. AI コパイロットがモックモード（フォールバック）で動作することを確認

モックモードでは:
- AI の回答は「現在AIサービスは利用できません」等の固定メッセージを返す
- クイズ機能・問題表示は正常動作

復旧手順:
- GEMINI_API_KEY を元の値に戻す
- Vercel が自動再デプロイ

### B-2: /admin/* 一時クローズ

管理機能のみ一時停止したい場合:
- next.config.js または middleware.ts で /admin へのアクセスを 503 にリダイレクト
- ただし通常は不要。Basic Auth でアクセス制限済みのため一般ユーザーへの影響なし

### B-3: 高負荷時のrate limit強化

AI コパイロットのリクエストが急増してコスト上限に近づく場合:

現在の設定:
- 無料: 1日30回（lib/rate-limit/server.ts）
- プレミアム: 1分10回ソフトリミット

一時強化手順（緊急時のみ、ユーザー確認必須）:
1. CLAUDE.md の「承認必須事項」にある「レート制限値の変更」に該当するため、
   変更前に必ず自分で判断を確認する（Dispatchの場合はユーザーに確認）
2. lib/rate-limit/server.ts の FREE_DAILY_LIMIT を引き下げる
3. PR を作成してマージ → Vercel デプロイ

## 緊急連絡・エスカレーション

### 本人の障害対応優先順位

1. Vercel Dashboard でデプロイ状況確認（2分以内）
2. Sentry で障害の原因特定（5分以内）
3. 部分停止 or ロールバックの判断（10分以内）
4. Twitter でユーザー告知（判断後すぐ）
5. 修正PR作成 → デプロイ（1〜2時間以内）

## ロールバック後の再デプロイ手順

ロールバック後に修正を加えて再デプロイする場合:

1. ローカルで修正を加える
2. git push → PR 作成 → main マージ
3. Vercel が自動デプロイ
4. https://www.kakomon-ai.jp で正常動作を確認
5. Twitter で「復旧しました」告知
