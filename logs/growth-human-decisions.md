# 集客・収益化フェーズ 人間判断事項（ループは実装せず・ここに積む）

ループが「これは社長/人間の意思決定が要る」と判断したものを積む。ループは戦略・料金・契約を勝手に確定しない。
各項目: 何の話か（平易に）/ なぜループが決めないか / 選択肢 / 推奨（あれば）/ 緊急度。

## セッション0 時点で既に判明している人間判断事項

### HD-1: GSC「Not found (404)」の実URL一覧をエクスポートして共有（最優先・ループ取得不可）
- 何の話か: 検索エンジンに「ページが無い(404)」と記録されている4,363件の**実際のURL一覧**。これが分かれば、復活すべきか・捨てるべきか・どこへ転送するかを的確に処理できる。
- なぜループが決めないか: GSCはログイン必須でループからは中身を取得できない。ループはコード側で分かる「削除済みページの転送漏れ」は塞げるが、4,363件の正体は一覧が要る。
- 人間がやること: GSC → ページ → 「見つかりませんでした(404)」をエクスポート（CSV）し、リポジトリに置く or 共有。ループ/人間がパターン分類して処理。
- 緊急度: 朝〜数日内（クロール資産回復の起点）。

### HD-2: フリーミアム課金の「価格」と「有効化タイミング」
- 何の話か: 午後AI採点の詳細版/回数無制限を有料にする場合の値段と、いつ課金を有効化するか。
- なぜループが決めないか: 価格・課金有効化は経営判断（CLAUDE.md承認必須）。今は埋もれているので課金の壁は流入を減らすリスク。ループはUIを「作るが未有効化」までに留める。
- 推奨（戦略より）: 認知が立つ10月前まで無料維持。価格は後日決定。
- 緊急度: いつでも（10月前に判断できればよい）。

### HD-3: アフィリ提携先の追加・タグ変更
- 何の話か: 午後対策の高単価講座（itec/スタディング/大原/TAC）等を新規アフィリ提携するか。既存はAmazon/楽天（タグは env 既存値）。
- なぜループが決めないか: 新規提携契約・アフィリID変更は承認必須。ループは既存Amazon/楽天実装の流用に留める。
- 緊急度: いつでも（高単価講座の提携は収益効率を大きく上げる候補）。

### HD-4: 午後AI採点（/[exam]/afternoon）の練習データが「モック」— 旗艦を前面化する前にデータ整備の判断が要る（セッション2発見）
- 何の話か: 旗艦＝午後AI採点の各試験ページ `/<exam>/afternoon` は 200 で公開済だが、**練習問題データがモック**（`data/questions/afternoon/ap/index.ts` に「実データはモック。本番データは scripts/parse-afternoon/parse-ap-afternoon.ts で生成」と明記。AP は各年季2問のみ）。ページは「【練習用】〜（AI採点ベータ）」「実際の過去問ではありません」「AI採点は目安」と免責表示あり。応用情報午後（道場の空白＝旗艦の本丸）/ FE科目B（土台）も同様にモック。
- なぜループが決めないか: ①モックのまま AP/FE ハブに「旗艦CTA」を大々的に追加すると、薄い練習コンテンツを誇大に見せる「過大修正の罠」＝CLAUDE.mLの「誇大表現を避け事実ベース」に反する。②兄弟の記述区分(sc/nw/db/es)が意図的に「Coming Soon」無リンクにしているのも、この採点品質/データ準備の未完を反映していると見られる。「Coming Soon→実リンク化」や「AP/FEへCTA追加」はプロダクト準備状況の判断＝経営/人間の意思決定。
- 選択肢: (a) `scripts/parse-afternoon/parse-*-afternoon.ts` で**本番の午後過去問データを生成・投入**してから前面化（旗艦を本物にする本筋・工数大）。(b) モックのまま「ベータ・練習用」と明示した控えめCTAを AP/FE にも出す（兄弟記述区分と整合させる形で）。(c) 当面は導線そのまま（既存st/sa/pm/sm/auの404修正のみで止める）。
- 推奨（戦略より）: (a) が旗艦を埋もれさせない本筋。最低でも応用情報午後の実データ投入を優先。データが揃うまでは誇大にしない。
- 緊急度: 中〜高（旗艦の核。ただし「データが薄いまま大きく見せる」愚を避けるため、データ整備とセットで判断）。
- 関連: backlog P1-2（AP/FE CTA追加は HD-4 の判断待ち）/ P1-4,P1-5（不安系キーワードの**オリジナル記事**で午後採点へ送客するのはモックデータに依存しないので先に進められる）。

### HD-5: 論文区分の個別essay記事の「AI採点」深リンクが noindex,nofollow の `/essays/[exam]` を指す（equity vs UX relevance のトレードオフ・セッション8発見）
- 何の話か: 論文5区分(pm/st/sa/sm/au)の個別essay記事(pm-goukaku-ronbun / st-senryaku-shikou / sa-architecture-tradeoff / sm-itil-storytelling / au-audit-evidence-language)本文に「[PM 論述添削](/essays/pm)」「[PM 午後II 論述AI採点](/essays/pm)」等の**採点intentの深リンク**がある（generators.ts 1604/1649/1692/1730/1770/3874/3999/4109 等）。その行先 `/essays/[exam]` は **`robots: { index: false, follow: false }`（noindex かつ nofollow・実測確認）**。一方、旗艦の indexable な集約ハブは `/essay`（robots無指定＝index可）。
- なぜループが決めないか: トレードオフが本物。`/essays/[exam]` は「その区分の採点ツール＋業種別合格答案サンプル」を持つ**区分特化ページ**で、記事の文脈に最も関連する行先（UX的に正しい）。だが noindex,nofollow ゆえ内部リンク equity が旗艦に流れず、follow:false で**equity が通過すらしない**。equity観点では indexable `/essay` 寄せが筋だが、汎用ハブへ送ると区分特化のUX価値（業種別サンプル等）を失う。どちらを取るかは情報設計判断。なお「業種別合格答案」intentの深リンク(7546/7856-7861)は /essays/[exam] が正しい行先で変更不要。
- 選択肢: (a) `/essays/[exam]` を indexable 化（robots除去 or index:true）して区分特化ページ自体を検索資産にする（薄い/重複ページ量産のリスク評価が要る＝設計判断）。(b) 採点intentの深リンクを indexable `/essay` へ寄せる（区分特化UXを一部犠牲）。(c) 現状維持（区分特化UXを優先・equityは header/home/footer/q-page の /essay 露出で別途確保済）。
- 推奨（戦略より）: 当面 (c)。旗艦 /essay はグローバル3面＋/q問題ページで既にクローラブル露出済（session4/7）。区分特化ページのUX価値を保ちつつ、indexable化(a)は「区分ごとに固有で厚い内容があるか」を見てから。
- 緊急度: 低〜中（旗艦露出は別経路で確保済。設計判断なので腰を据えて）。
- 関連: backlog P1-5「新規(未着手・要慎重)」。セッション8で SKIP（自律実装せず本HDへ）。

### HD-6: ブログ記事 `sc-ronbun-taisaku` がSC午後を「論文(論述)試験」と誤記載＝事実誤り確定（セッション17・IPA公式で検証）
- 何の話か: 公開ブログ記事 `情報処理安全確保支援士 午後II論述対策｜合格論文の書き方`（generators.ts L3514〜・slug `sc-ronbun-taisaku`）が、SC午後IIを **論文(論述)試験**として詳細に記述（「午後IIは論述試験です」「120分・2問から1問選択・設問ア〜ウ・合計3,200字前後の合格論文」等）。だが **SCに論文(論述)試験は存在しない**。
- 検証（ループがIPA公式で確認済・従来は"懸念"止まりだった事実を確定）: IPA公式によると **SCの午後試験は記述式**（多肢選択式・記述式）。2023年改定で **午後I・午後IIは統合され「午後」1本（記述式）** になった（[IPA SC試験](https://www.ipa.go.jp/shiken/kubun/sc.html) / [出題構成変更2022/12/20](https://www.ipa.go.jp/shiken/syllabus/henkou/2022/20221220.html) / [試験要綱Ver5.3](https://www.ipa.go.jp/shiken/syllabus/nq6ept00000014lt-att/youkou_ver5_3.pdf)）。SCは過去も含め**一度も論文(essay)試験ではない**（論文区分はST/SA/PM/SM/AUの5区分のみ＝ESSAY_EXAM_CODES）。よって本記事の「午後II」「論述」「合格論文」「設問ア〜ウ3,200字」は事実無根の捏造フォーマット（論文区分の体裁を流用したもの）。
- サイト内の他箇所は正しい: generators.ts L2949は「SCの午後Iは技術の深い理解（記述）」と正しく分類、旗艦/essay・アフィリ(category=午後)もSCを論文扱いせず記述で正確（session12「SC論文 誤framing回避」）。**矛盾源は本記事のみ**。
- なぜループが決めないか: 記事の前提(タイトル・本文・字数配分)全体が捏造フォーマットで、**最小diffでは是正不能**。選択肢=(a)SC午後=記述式の実態に合わせて全面リライト（工数大・要事実精査）/(b)記事を削除し410 or 関連SC記事へ301（sitemap/内部リンク/funnelへ波及）/(c)現状維持（=誤情報を放置）。記事の存廃・リライト方針は情報設計＋編集判断で、prior session(3)が既に人間預かりにしていた案件。削除は routing/sitemap に波及するため自律実行しない。
- 推奨（事実性より）: (a)記述式の実態に合わせたリライトが筋（SC午後＝150分・大問選択・記述式。"論文/合格論文/設問ア〜ウ/字数配分"を削除し、記述式の解答設計＝下線部の根拠・字数指定記述の組み立て等へ）。少なくとも**「論文」「論述」「合格論文」「午後II」表記は事実誤りなので早期に外すべき**（誇大/誤情報＝CLAUDE.md「事実ベース」違反・受験者を誤誘導）。リライト工数が出るまでの暫定で(b)も可。
- 緊急度: 中〜高（live状態の事実誤り。SC受験者を誤った試験形式で誤誘導するため、放置の害が他HDより直接的）。
- 関連: backlog P1-5「SKIP（SC午後framing事実性が懸念）」/ P2-2「sc-ronbun-taisaku はSC午後frame事実性がHD未決」。本HDで懸念→**事実誤り確定**に格上げ。

### HD-7: 2026年度からの大規模制度変更（CBT移行・「春期/秋期」→「前期/後期」名称変更・試験月の変更）でサイト全体の前提が更新を要する（セッション19・IPA公式で確認）
- 何の話か: サイト全体が「春期＝4月・秋期＝10月」の紙試験前提で書かれている（generators.ts/各記事/exam-data 等で多数）。だが **2026年度（令和8年度）から AP・高度試験・支援士試験は CBT方式へ移行**し、**「春期・秋期」が「前期・後期」へ名称変更**、さらに**実施月が変わる**（IPA公式の実施予定では **前期＝2026年11月頃**・**後期＝2027年2月頃** と読める）。
- 検証（ループがIPA公式で確認）: [2026年度実施予定](https://www.ipa.go.jp/shiken/2026/ap_koudo_sc_yotei.html)（前期=ST/SA/NW/SM/SC+AP、後期=PM/DB/ES/AU/SC+AP・「前期/後期へ名称変更」「日程は決まり次第」）/ [CBT移行案内](https://www.ipa.go.jp/shiken/2026/ap_koudo_sc-cbt.html) / [プレス2025/08/12](https://www.ipa.go.jp/pressrelease/2025/press20250812.html)。区分グルーピング自体（前期=旧春期/後期=旧秋期）は[令和7年度春期](https://www.ipa.go.jp/shiken/2025/r07haru_exam.html)と同一＝セッション19で個別記事の誤グルーピングは是正済（NW=春/PM・AU=秋）。
- なぜループが決めないか: ①影響が**サイト全体**（「春期(4月)」「秋期(10月)」「年2回」「実施月」表記が多数の記事・テンプレ・exam-data・FAQ・JSON-LDに散在）＝最小diff/1論点の原則を超える広域変更で、自律一括置換は誤爆リスク大。②**移行期の表現方針が編集判断**（新旧併記するか/いつ切り替えるか/「2026年度より前期・後期へ」注記を全体に出すか/CBT通年化に伴い「年2回」自体が変わる可能性）。③IPA側の日程詳細が「決まり次第」で**未確定要素**が残る（月の確定情報を待つべき箇所がある）。
- 選択肢: (a) 移行が確定・周知されたタイミングで、春秋→前後期＋実施月をサイト全体で一括更新（SSOT化＝exam-data等に「実施時期」フィールドを設け一元管理してから展開するのが安全）。(b) 当面は主要な高可視記事にのみ「2026年度より『前期・後期』へ名称変更・CBT移行予定（最新はIPA公式で確認）」の注記を足す軽量対応。(c) 現状維持（IPA日程確定まで動かない）。
- 推奨（事実性より）: まず (b) の軽量注記で誤誘導を緩和しつつ、(a) の SSOT 化＋一括更新を IPA 日程確定後に計画。グルーピングの事実誤り（個別記事）はセッション19で是正済なので、残るは「春秋/月/年2回」の枠組み表現＝設計を伴うため人間判断。
- 緊急度: 中（2026年度＝直近。ただし枠組み変更は広域＆IPA日程未確定要素があるため、SSOT設計と確定情報待ちをセットで）。
- 関連: セッション19で個別記事 `ap-goukaku-go-koudo-senryaku` の春秋グルーピング誤りは是正済（`ed5d0d6`）。site-wide な春秋→前後期/月/年2回 の枠組み更新は本HD。
