# Apple審査アクセスの結論とコード発行案（ASC3）

2026-11-05にApple公式情報を確認。

## 結論

本アプリはログイン後の課金・復元・事前保存・意見送信による追加10問を持つため、
**有効なデモアカウント等で会員機能を審査できるアクセスが必要**。
匿名で最初の10問・解説等を確認できても、会員機能の審査アクセスの代わりにはならない。

- **2.1(a)** はログインがあるアプリにデモアカウント情報と稼働するバックエンドを求める。
  法律上・セキュリティ上の義務でアカウントを提供できない場合、Appleの事前承認を得て、
  全機能を示す組み込みデモモードを代替とできる。Claudeが秘密を入力できない事情だけで免除にはならない。
- **Before You Submit** は会員機能がある場合の有効なデモアカウントまたは全機能のデモモードによる
  full accessと、審査期間中のバックエンド稼働を求める。
- **2.1(b)** はIAPが審査担当者から見つけられ、動作することを求める。
- **5.1.1(v)** は重要なアカウント依存機能がなければログインなし利用を認めること、
  アカウント作成を提供するならアプリ内削除を提供することなどを定める。
  デモアカウント不要を定めた条項ではない。

公式: [App Review Guidelines（2.1）](https://developer.apple.com/app-store/review/guidelines/#app-completeness)、
[5.1.1](https://developer.apple.com/app-store/review/guidelines/#data-collection-and-storage)、
[Before You Submit](https://developer.apple.com/app-store/review/guidelines/#before-you-submit)。

これは条文を本アプリに当てはめた判断であり、審査通過の保証ではない。
匿名画面のスクリーンショットは通常利用の実画面で構成し、デモモードとは称さない。
既存IOS3の審査コードは専用の無料会員へ正規ログインする方式で、全会員機能を自動解除しない。
通常無料枠・追加10問の使用済み状態・AI上限と、有料機能の審査用購入・復元の可否を事前確認する。
使用済みの追加特典を本番DBで勝手にリセットせず、再確認手順・必要な審査データを担当者が用意する。

## 提案のみ：本番サーバー側の期限付きコード発行

現行 `APP_REVIEW_CODE_SHA256` / `APP_REVIEW_EXPIRES_AT` と専用IDの設計を引き継ぎ、
Codemagicへ生コードを保存しない経路を次の別タスクで用意できる。

1. オーナーの認証済み管理画面または管理コマンドで、審査期間専用の高エントロピーコードを生成する。
   サーバーにはハッシュ、期限、失効状態と値を含まない監査記録だけを保持する。
2. 生コードはオーナーに一度だけ表示する。オーナーがASCの対象版のPassword欄へ直接入力する。
   Claude、URL、Git、Codemagic変数、artifactへ渡さない。登録済み審査情報はASC3の既存モードで保持する。
3. 審査完了まで十分な期限を確保し、再審査時は延長・再発行とASC更新を同期する。
   ログイン時のレート制限、専用ID固定、期限切れ拒否、通常PKCE復帰を維持する。
4. オーナーが提出対象アプリでログイン、+10問の手順、審査用購入・復元を確認してreadyを設定する。
   有料権利をコードで偽装せず、審査用購入環境で確認する。全機能へアクセスできない場合は提出しない。
5. 審査終了時に失効し、必要なら既存セッションも無効化する。

この発行UI/API、権限設計、秘密の保存・表示・本番設定変更はASC3では**実装していない**。
既存の有効なIOS3コードがあればオーナーが直接ASCへ一度登録する経路は利用できる。
Apple事前承認の全機能デモモードは別案だが、未実装・未承認のため今回の提出条件には採用しない。
