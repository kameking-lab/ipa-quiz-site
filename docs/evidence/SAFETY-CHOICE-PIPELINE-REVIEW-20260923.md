# 安全系直近2年：全肢レビューの再開設計

対象は免許試験 lckohyo 1,344問、作業環境測定士 emkohyo 360問。公開データの書換えは行っていない。

## 独立監査で確認した障害

1. lck `author_and_review` はバッチ中の1問だけ独立レビューし、そのPASSで全問を受け入れる。全問全肢の独立確認とは呼べない。既存受入を削除せず、未検査問を追検査する必要がある。
2. lck の再利用キーは原文・公式正答・肢数だけで、図の実バイトと年度が含まれない。同一原文でも画像や適用法令が変わり得る。73組／73問の再利用候補はあるが、自動PASSにはしない。
3. lck の候補キャッシュに同一IDの異なる草稿が3件存在する。新しいものを無条件に選ばず、どれを修正正本にするか確定する必要がある。対象は計画JSONの `candidateConflicts`。
4. EMの195候補中113問は `sources` 欠落で静的ゲート不合格。ここへOpusレビューを投入しても通らない。先に政府資料を紐づけるべき。
5. EMの既存受入は候補SHAと根拠パックSHAを保持する一方、元画像差し替えや出題年月の変化を直接無効化しない。追加receiptでこの差分も固定する。
6. 5時間枠制限中のキュー継続・同一のHOLD再試行は無駄になる。今回の追加ランナーは呼出し失敗で停止し、各バッチ完了時に問単位のreceiptを保存する。

## 追加したもの

- `scripts/safety_choice_review_gate.py`: 原文・公式正答・図の実バイトSHA・出題年月/PDF SHA、解説、根拠パックをまとめて固定する。5肢の個別PASS、全表示根拠URLの照合、出題時の適用、公式正答との照合をすべて要求する。サンプルPASS、未確認、矛盾はHOLD。
- `scripts/review-safety-choice-clusters.py`: 同じ資格の問題を引用URL順に束ね、最大6問を1レビュー要求にする。根拠パックを1回だけ共有し、各問の独立判定を保存。1問のFIXで別問のPASSを破棄しない。現在の入力と一致するPASSは次回スキップする。
- `scripts/test-safety-choice-review-gate.py`: 同じ画像パスの実体差し替え、年度変化、解説差分、根拠差分、未確認肢、正答矛盾、偽政府URL、原図欠落を試験。

この追加receiptは既存EM receiptを未実施扱いにするものではない。新しい厳密な形式に未移行の既存PASSも `reviewPending` になる。公開件数は別の既存statusで計測する。

## 実測（2026-09-23 の作業中スナップショット）

- lck: 候補26問→5クラスタ。個別26回に対してCLI要求数を約81%削減できる計画。独立チェックの対象問数は26のまま。
- EM: 静的適合82問→15クラスタ。個別82回に対してCLI要求数を約82%削減できる計画。113問は根拠欠落のためレビュー前HOLD。
- 8テストPASS。CLI枠制限中のため新ランナーからモデルを呼んだ実行時間・トークン・合格率は未測定。上記はリクエスト数の削減でありトークン削減率ではない。

## 回復後の順番

1. lckの相反草稿3件を担当者が特定して古い候補を別保管。EMの根拠欠落113問に政府一次資料の該当条文・頁と取得SHAを入れる。一般ページのタイトルだけでは不可。
2. 各担当の既存執筆ランナーを継続。ただしlckのサンプルレビューだけで公開完了にしない。
3. 次の追加ランナーを各worktreeに向けて実行。共通Claude枠で全レーン合計の同時実行数を管理する。このランナー自体は直列。`--max-batches` は少量から開始する。

```powershell
py -3.12 scripts/review-safety-choice-clusters.py --root C:/Users/kanet/20260522/ipa-lckohyo-choices-20260923 --group lckohyo --review --max-batches 5
py -3.12 scripts/review-safety-choice-clusters.py --root C:/Users/kanet/20260522/ipa-emkohyo-2025-choice --group emkohyo --review --max-batches 15
```

4. `docs/evidence/<group>-full-choice-review-ledger.json` の問単位HOLDを修正。候補や根拠を変更すると旧PASSは自動無効になる。既存公開データへの採用は担当者の既存受入ランナーと全体coverage gateを使い、追加receiptも確認する。
5. 全件カバーを満たした時点で、既存厳密coverage gate・画面表示・本番確認を行う。このランナーは公開JSON/coverage contractを変更しないため、実行だけで公開完了にはならない。

## 残るリスク

モデルの自己申告PASSだけでは内容の真実性を証明できない。一次資料の直接照合が必要。図表やJIS固有値の出典不足、公式正答と原文の矛盾は引き続きHOLD。引用URLの政府ドメインという条件だけでも十分ではなく、根拠の該当箇所と出題時点を確認する。

既存lckの全肢レビュー前受入と年度をまたぐ自動再利用は本体側で別途制御が必要。今回の変更は共有データを保全するため独立レイヤーとして追加したものであり、既存ランナーを自動で差し替えてはいない。
